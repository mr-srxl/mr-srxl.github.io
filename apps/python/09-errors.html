09 · Errors & exceptions

Programs break. That's normal. What matters is how gracefully they break — and how clearly they tell you what went wrong.

Meeting the common errors

SyntaxErrortypo — missing colon, unmatched bracket
NameErrorused a variable that doesn't exist
TypeErrorwrong type — "a" + 1
ValueErrorright type, wrong value — int("abc")
IndexErrorlist index out of range
KeyErrordict key doesn't exist
FileNotFoundErrorthe file isn't there
ZeroDivisionErrordivided by zero

try / except

try:
    n = int("hello")
except ValueError:
    print("That wasn't a number.")
That wasn't a number.

Catch specific errors. Catching everything (except: alone) hides bugs you'd rather see.

try:
    value = int(input("Enter a number: "))
    print(10 / value)
except ValueError:
    print("Not a number.")
except ZeroDivisionError:
    print("Can't divide by zero.")
except Exception as e:
    print(f"Something else went wrong: {e}")

finally — always runs

Use finally for cleanup that must happen whether or not an error occurred.

try:
    f = open("data.txt")
    content = f.read()
except FileNotFoundError:
    print("No file — starting fresh.")
finally:
    print("Done trying.")

In practice, with open(...) handles the cleanup for you. But finally is still useful for other resources.

Raising your own errors

def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative.")
    return age

set_age(-1)
# ValueError: Age cannot be negative.

Raising an error early is often the kindest thing you can do — it stops a bad value from flowing through the rest of your program.

Custom exceptions

class LoginError(Exception):
    pass

def login(user):
    if not user:
        raise LoginError("Username is empty.")

try:
    login("")
except LoginError as e:
    print(f"Login failed: {e}")
Try this: write a function safe_divide(a, b) that returns a / b, but catches ZeroDivisionError and returns None instead of crashing. Then call it with (10, 2) and (5, 0).
